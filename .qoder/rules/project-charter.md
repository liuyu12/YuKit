# YuKit 项目章程

## 身份与边界

- 技术栈：Spring Boot 4.1.3 / JDK 21 / Sa-Token 1.46.0 / MyBatis-Plus + Flyway / MapStruct / JUnit5 + Mockito。包根 `cn.lycoder.boot`。
- 模块：`yukit-dependencies`（BOM）、`yukit-framework`（`yukit-common` + 5 个 starter）、`yukit-module-system`（业务）、`yukit-server`（组合根）。
- 禁改：`flyway_schema_history`、已发布的 `V*.sql`、`target/**` 与生成物（MapStruct 的 `*ConvertImpl` 不入库）。
- 破坏性操作（清库、`git reset --hard`、`push --force`、批量删文件）一律先停下确认，不绕过阻塞改用强制手段。

## 不可逆红线（机器查不出、且后果静默）

1. **跨表引用校验必须过滤逻辑删除位**——否则已删记录永久占用被引用对象，接口照常、数据是错的。两套删除语义见「数据库迁移与单测约定」。
2. **超管（`userId=1`）在 `StpInterfaceImpl` 返回 `"*"` 通配放行全部权限码，与 `sys_role_menu` 无关**。禁止为 admin 逐条补授权行，也不要用"插一行后能调通"反证原本缺权限。
3. 密码、token 等敏感字段不得进审计日志；改密成功须 `kickout` 使全端下线——只失效当前 token 会留下旧端继续可用的越权窗口。
4. 动态 `LIMIT`、排序字段等拼接只允许用 int 型变量，拼字符串即注入面。
5. 跨全表的只读校验（账号唯一等）必须加 `@IgnoreDataPermission`，否则被部门数据范围静默截断。

## 协作协议

- 动手前先 grep 同类实现找先例（`notice` / `config` / `post` 是 CRUD 族模板），不按通用最佳实践直接写。
- **写/改 Java 前先取用 `sonar-redlines.md` 与 `java-layering.md`**（含库版本禁忌）。
- 结论要带证据：说"已确认"必须附验证方式；只做单向验证时明说"未做对照实验"；不确定就说不确定。
- 库版本 API 判断先查代码或 jar 内类，不凭记忆——本项目已多次出现"记忆里是旧版方法名"。
- 预计改动超过 200 行或跨 3 个以上模块时，先给方案再动手。
- 规则冲突或与代码实况不符时，以实况为准并提示我更新规则。

## 规则更新触发信号

出现下列情形，主动询问我是否固化进规则，**不要擅自改文件**：

- 同一约定我在对话里解释了第二次
- 我纠正了你一个自认为正确的做法
- 冒烟或测试暴露出可复现的新坑（库版本、工具行为、环境差异）
- 新模块落地，形成第 N 次重复的同一套惯例

提议时一并给出：写进哪个文件、用什么触发方式、有无可下沉到 lint / CI 的部分。**一次性的坑只进记忆，反复出现的才进规则**——判据是出现次数，不是重要程度。

## 规则自身的维护约定

- **同一事实只在一处成文**，其余写"见某文件"；重复条目一旦腐化就是互相矛盾的指令，比缺规则更有害。
- 能下沉到 lint / CI 的不进规则；易变数字（版本号、表数、用例数）一律写"实查入口"，不写死。
- 带历史包袱的条目必须写明**失效条件**，避免把过渡状态固化成永久规范。
- `> 最近核对：<commit> / <日期>` 里的 commit 指**核对所依据的代码提交**，非规则文件自身提交。
- 预算：`always_on` 合计控制在 3K 字符内——它是唯一每轮必注入的通道。
